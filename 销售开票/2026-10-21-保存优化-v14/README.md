## 内容（只动 main.js、server.js，行为等价）

1. **O2 lastsaledt 批量化**：存在性一次查（DBUtil.openDataSet，服务端有据 API）、内存中按原顺序逐行分类（同单同商品"先插入后转更新"语义精确复刻）、写语句文本与原逐行版逐字相同、最后两批写入。
2. **O1 删重复查询**：before_save 的 WMS 分支误把 IsEnd 查询执行了第二遍，删除并复用已有结果。顺带查明："已同步 WMS 不允许调整"校验因查错 SQL 从未生效——本版为保持拦截行为未修，待业务确认。
3. **O4 Upd_SrcBill 合并**：同（来源单号，行号）多行 num 求和合并一条 UPDATE（等价推导见变更文档），单行组逐字原语句。
4. **O3 删死代码**：5 处从未执行的赋值（S_ClientSZ 两处、KT_ybillxgjlsqlafter 三处，即模块关系图异常 R5），实际执行语句不变，DB 收益计 0、不充数。
5. **O5 限销日期边界缓存**（main.js）：Sql_MM/MM1/YY/YY1 是当前年月的纯函数，按月/年键缓存；与行相关的配置/已购量查询不缓存。导入失败提示版本标记随版改为 (v14)。

导入管线、税率归一化、快照、回读校验未动；XUL/props 与 v13 逐字节一致。Node mock 新旧等价对照 37 项全过（最终表状态/拦截结果/提示文案一致）。

## 现场验证点

1. 同单计时：部署前用一张 20–30 行典型单测保存秒数（同单同时段 2–3 次取中值），部署后用同一张单的副本同法对比。
2. 保存含重复商品、多批号拆行的单：最后售价（客户-商品维度）的售价/售量/批次与部署前同单操作一致。
3. 修改保存一张旧单：订单执行量、领用单已售量与部署前同操作一致。
4. 启用限销的客户：月限/年限拦截行为与提示文案与部署前一致。
