## 改了什么（相对 v18，只加细分计时，且只改 main.js）

v18 现场首读：检查一遍 4,621ms，但只有总段没有分布。本版把检查遍里 5 个昂贵校验逐个分桶，弹框在原有各行之外新增「检查细分」一段，供 Alan 圈定要关的校验：

1. **五校验分桶**：跨月 Kpf_UpdDateCheck、警戒量 kf_chkBal、库存 pf_chkBal、信贷 pf_chkCredit、价格 pf_ChkBillPrice，各自单独计时。包装统一用「先存临时变量 → 计时 → 按原条件判断」，短路语义与返回值（含价格校验的最终 return 透传）不变。
2. **警戒量未启用如实显示**：kf_chkBal 由 useKCJJ 门控，未跑时弹框显示「未启用」（哨兵 -2），不显示 0。
3. **限销段单列**：保存检查遍内限销循环逐调用点打点（逐行 pf_zdychkLimitSale + uf_compute，内含 uf_spkhxx 判定）；拦截行已花耗时也留得下。编辑期另一处同名调用不在检查遍内、不计入。
4. **检查其余闭合**：其余 = 检查总段 − 各桶之和，账目对得上。
5. 服务端 server.js、props.json 与 v18 **逐字节一致**；弹框原有各行全部保留（仅标题版本字样 v18→v20细分）。

全部计时语句 try/catch 包裹，计时失败不影响保存。验证：node --check / XUL / props 解析全过；mock 合计 155 项全过（新写细分计时 60/60——11 场景与 v18 对照放行/拦截/调用序/实参逐一相同、分桶精确值与账目闭合、弹框逐行渲染；复跑 v18 三套回归：限销 53/53、回读/报告/包装 26/26、检查链组合 16/16）；反向解包逐字节复验通过（除 main.js 外 6 文件与 v18 逐字节一致）。
