## 4. Node mock 实跑（真实函数体） —— 46 项断言全过

方法：从**成品** main.js/server.js 中按名抽取真实函数体（括号配平抽取，非复制改写），在 Node 中以平台对象替身（FakeDataset 实现 fieldCount/field(i).fieldName/getValueAt/recordCount；DBUtil 捕获 SQL；DsMain 假对象记录 field 赋值）运行。业务逻辑零替身。

服务端匹配核心 `uf_matchImpData` + 回调 `Srv_ImpClientBack`：
- 形态甲按标题全命中、未知列入清单、多行只取第一行；
- 形态甲按字段 id 命中（大小写不敏感）；
- 形态乙（位置列名 + 首行表头）：表头不计行数、数据从第二行起、未匹配列取自表头行；
- 重名标题「备注」：双列按模板顺序分配 KF_REMARK→Remark；单列落 KF_REMARK；
- 空文件（0 行）、只有表头一行：行数 0、无回写值；
- 回调全链：先 delete 本批次暂存，再逐字段 insert（含值经 sqlEncode 转义的断言）、@rows/@unmatched 元信息行落暂存。

客户端 `uf_importExcel` / `uf_exportMb`：
- importFile 入参（"dataset" / 回调名 / EntId / K_OnlyId 取号）逐项断言；
- 暂存行解析后逐字段回写当前行（逐字段断言写入值）；已有当前行不 append、无当前行先 append 一次；
- 提示文案口径：回写字段数、总行数与「只回写第一行」、未匹配列清单、「尚未保存」四要素齐全；
- 空数据提示、零匹配提示两条分支均不回写；
- view 态拦截：不调用 importFile、只提示；
- 模板导出：openEmpty → append 一行 → 示例值（单位名称/18 位信用代码）落位 → grid_mb.exportTo(0)。

端到端一条：形态乙 Excel 经服务端真实回调生成暂存 SQL → 解析回暂存行 → 喂客户端真实回写函数 → DsMain 收到第一行两字段，未匹配列出现在提示中。
