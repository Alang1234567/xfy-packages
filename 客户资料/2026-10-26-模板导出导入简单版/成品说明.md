## v1.1 热修（2026-10-26，修 Excel 导入现场报错）

- **现场现象**：导入 v1 后两按钮正常出现，点「Excel导入」选文件后弹错：`Excel导入失败：parameter: onlyid is not evaluated`，回写未发生。
- **根因**：回读宏 `uf_sql_impback` 的参数声明与客户端实参键对不上名。宏 SQL 写的是 `K_OnlyId= :onlyid`，而 `uf_importExcel` 传给 `ds_impback.open(...)` 的 params 里这批号的键是 `K_OnlyId`（该键同时供 `FormUtil.importFile` 一跳——服务端回调按此键名取全局量 `K_OnlyId` 写暂存表，那一跳是对齐的）。本平台宏参数按**声明名精确绑定**（本表单生产代码三处实证：`sql_chkCCode` 的 `:entid/:code/:businessid`、`S_ChkClient` 的 `:BusinessName/:OrgCert` 与 `#if(FldName)`、`uf_sql_citylast` 的 `:city`，调用方键名均与声明逐字一致）；另一个参数 `:entid` 是平台上下文参数（`uf_ChkClient` 不传 entid 键、`S_ChkClient` 照常工作），可自动求值，所以报错只点名 `onlyid`。
- **修复（一处）**：宏 SQL `:onlyid` → `:K_OnlyId`，与 params 键逐字一致（混合大小写参数名在本表单有 `:BusinessName/:OrgCert` 先例）。main.js / server.js / main.xul 与 v1 逐字节不变；props 仅此一 token 变化（自验已做 v1↔v1.1 逐成员对账）。
- **新增防线**：自验脚本新增「宏参数契约对账」——包内每个被 `ds.open` 调用的宏（4 处）逐一比对声明参数集与调用点实参键集，外加 importFile 一跳的服务端环境名 ⊆ 客户端实参键校验；fixture 新增完整调用序列用例（生成批次号 → importFile → 真回调写暂存 → 按契约 open 回读 → 逐字段回写）与两个负控，其中负控 A 用 v1 宏文本 + v1 实参可**原样复现**现场报错 `parameter: onlyid is not evaluated`，证明该防线能拦住此类问题。
- 导入说明不变：导 v1.1 包后关掉全部已打开的客户资料页签再重开测试。
- 功能定案（Alan 2026-10-26 16:47）：就在本页加两个按钮，简单实现——按列名匹配、回写当前页面字段。上一版克隆独立导入表方案已作废，本包不含其任何功能面。

## 两个按钮（主工具栏，与「保存」同排，位于「匹配地址」之后）

| 按钮 | id | oncommand | 作用 |
|---|---|---|---|
| 模板导出 | `toolbar.m10` | `uf_exportMb()` | 导出一个 Excel 模板：55 列，列名 = 字段中文标题（format 标题），含一行示例数据 |
| Excel导入 | `toolbar.m11` | `uf_importExcel()` | 选 Excel → 按列名匹配 → 把第一行数据回写到当前页面对应字段（**只回写不落库**，落库仍走原生「保存」与其原有校验） |

## 实现方式（全部走平台已取证机制，与销售开票同源）

**模板导出**：新增隐藏网格 `grid_mb`（display:none）绑定模板数据集 `ds_mb`（temptable `t_2p1teo4k24z55h5x_ds_mb`）。点按钮时先 `ds_mb.openEmpty()` 并 append 一行示例数据，再 `grid_mb.exportTo(0)` 导出。示例值取字段语义的浅显例子（如单位名称「示例医药有限公司」、信用代码 18 位示例号、省/市/县「四川省/成都市/锦江区」）；下拉字典类字段（客户性质、业务来源、业务平台、发票类型、结算方式、配送方式、价格体系、事业部、大区、客户标签、质检报告要求、线路等）示例行留空——填写时请按表单里该字段的**存储值**填，不要填显示名称。

**Excel导入**：点按钮 → `FormUtil.importFile("dataset", "Srv_ImpClientBack", params)`（params 带 EntId 与批次号 K_OnlyId，serialno "I" 取号）→ 平台在服务端把文件解析为全局数据集 `dataset` → 服务端回调 `Srv_ImpClientBack` 做列名匹配，把结果（字段id→值）逐行写入回写暂存表 `t_2p1teo4k24z55h5x_ds_impback`（数据集 `ds_impback`）→ 客户端经宏 `uf_sql_impback` 读回，逐字段 `DsMain.field(字段).value = 值` 写到当前行。

**列名匹配规则**（回调内 `uf_matchImpData`，契约表 = 模板 55 列的 [字段id, 标题]，随 server.js 走）：
- Excel 表头文字等于**字段标题**（如「单位名称」）或等于**字段 id**（如 `BusinessName`，大小写不敏感）都认；
- 数据源列名有两种形态都兼容：①平台以表头作列名——直接按列名匹配，全部行都是数据；②列名为位置名、首行是表头——首行按表头匹配，数据从第二行起；
- 有多行数据时**只回写第一行**，完成提示会注明总行数；
- 标题重名只有一处：「备注」对应两个字段——页面上方「注意事项」格（KF_REMARK）在模板顺序在前，下方「备注」格（Remark）在后；Excel 里出现两个「备注」列时按顺序依次分配，只有一个「备注」列时落到前者（KF_REMARK），要写后者请用列名 `Remark`；
- 没匹配上的列不报错、不中断，完成提示里会列出未匹配的列名。

**完成提示**（一次 alert 说清）：已回写字段数 / 未匹配列名清单（有时才列）/ 数据总行数（>1 时注明只取第一行）。空文件提示「没有可回写的数据行」；一行数据但零列匹配时提示未回写任何字段。值一律按字符串原样回写，不做数字/日期格式转换——填错格式由页面控件与保存校验（uf_saveChk）兜底。查看（view）状态下点导入会提示先进入新增/修改状态。

## 现场验证项（离线无法证实，导入后请按序确认）

1. **导包后先关掉客户资料全部已打开页签再重开**，工具栏「匹配地址」后应出现「模板导出 / Excel导入」两个按钮。
2. **模板导出**：点「模板导出」，确认导出文件能打开、含 55 列表头 + 1 行示例数据。若只有表头没有示例行（`openEmpty/append` 在 temptable 数据集上的行为差异），模板仍可用，把现象回传即可。
3. **导入形态一**：用导出的模板改几个值（删掉示例行、填一行真实数据）后点「Excel导入」选它，确认提示的回写字段数正确、页面字段被填上、未保存状态下关掉页面不落库。
4. **导入形态二**：另存一个只有标题+一行的 Excel（或手工做一个表头为字段id 的文件，如 `BusinessName`），确认同样能匹配回写——这一步验证平台解析出的列名形态与双形态兼容是否如预期。
5. **多行文件**：放 2 行数据导入，确认只回写第一行且提示注明总行数。
6. **暂存表**：首次导入时确认平台按 temptable 定义自动建表（`t_2p1teo4k24z55h5x_ds_mb` / `t_2p1teo4k24z55h5x_ds_impback`），若回调报缺表，回传报错原文。
7. **导入扩展名**：`FormUtil.importFile` 本次按销售开票现行三参调用（未传 extension）；若现场只弹得出 .xls 或对 .xlsx 报错，回传现象再补参数。

## 使用注意

- 导入只回写到**当前打开的这个客户页面**，不新建客户、不批量；要给哪个客户填，就先打开哪个客户（或新增页）再导入。
- 示例行导入前请删掉或直接覆盖填写；若示例行留在第一行，导入会把示例值写进当前页面。
- 字典/下拉类字段（客户性质、业务来源等）请填存储值；填显示名称不会自动转码（简单版定案口径），保存校验会拦下明显不对的值。
