## 一、六项改动逐处

### 1. server.js 时间写入（乙路线，修 ORA-12899）
- 单头更新 `K_ApplyTime=sysdate` → `K_ApplyTime=to_char(sysdate,'YYYY-MM-DD HH24:MI:SS')`（全包仅此一处写该列，保存/撤销共用）。
- 前提：字段先 `ALTER TABLE SaleOutMt MODIFY (K_ApplyTime CHAR(19));` 放宽并同步平台字典长度 19 —— 19 位时间串正好落满 CHAR(19)。

### 2. server.js 守卫 NVL 加固（修「已被他人修改」误报）
- `uf_readRow` 的 SELECT：`Num/TaxAmount/K_RegInvoiceNum/K_RegInvoiceAmt/K_ApplyInvoiceNum/K_ApplyInvoiceAmt` 全部 `nvl(...,0)`，标记读 `nvl(K_ApplyFlag,'N')`；JS 侧再对标记去空白、空回 'N' 双保险。
- 新增 `uf_guardedUpdate()` 收敛保存/撤销共用的带守卫更新：守卫两侧 NVL 归一，且比较面由「申请量额 2 项」扩为「申请量额 + 已登记量额 + 标记列」5 项；捕获 `DBUtil.update` 返回行数——返回数字时以恰好 1 行为成功判据、0 行或多行直接判冲突且文案为「守卫未命中」；取不到数字（平台不回行数）才回读复核，不一致文案为「回读不一致」。
- 失败回执统一：`数据已被他人修改（守卫未命中/回读不一致），写回/撤销未生效，请刷新重试`。

### 3. 标记列切换 KF_KFPSQ → K_ApplyFlag
- 现场已自加 `SaleOutDt.K_ApplyFlag CHAR(1) DEFAULT 'N'`，本版全面改用它，不再占财务预留的 KF_KFPSQ。
- 引用点：format 定义 2 处（ds_dt/ds_rdt 明细数据集字段改名，标题仍「是否发票申请」、checkbox `Y;N` 形态、默认值 `N` 不变）、props 宏 4 处（蓝/红明细 select 列 + 查询主宏 exists 条件 + 查询明细 where 条件）、server.js 功能引用 3 处（读现值 SELECT、守卫 WHERE、SET 子句）+ 头部注释同步。
- NULL 语义统一 NULL≡'N'（读与守卫都 NVL）；保存写 'Y'；撤销降至已登记且量额归 0 写 'N'。
- verify 断言：成品全部成员（含解码后的 format）`KF_KFPSQ` 残留 = 0。

### 4. 六宏 NVL 归一（共 41 处变换）
- sql_mt_list / sql_dt_list / sql_rmt_list / sql_rdt_list / sql_qmt_list / sql_qdt_list 中，`K_Reg*/K_Apply*` 参与的 greatest/abs/SUM/行出现条件/状态 CASE 全部先 `nvl(...,0)`；红字先 `abs(nvl(...,0))` 再 greatest；明细 select 的申请/登记四列改为 `nvl(...)` 输出（NULL 行在界面显示 0 而非空白）。
- 查询存在条件与标记列口径一致：`(nvl(v1.K_ApplyFlag,'N')='Y' or nvl(v1.K_ApplyInvoiceAmt,0)<>0)`（明细侧为 b. 别名同式）。
- greatest 余额口径本身（已登记与已申请取大）不变，只是给操作数套 NVL。

### 5. 查询宏 K_ApplyTime 直读（修 ORA-01722）
- sql_qmt_list：`to_char(a.K_ApplyTime,'YYYY-MM-DD HH24:MI:SS') as K_ApplyTime` → `a.K_ApplyTime as K_ApplyTime`（该列现为 CHAR 型，套日期格式转换必报 01722）。ds_qmt format 该字段本就是 char/sz=19，不动；GROUP BY 不动。此即现场已在服务器上手改过的同一行，导 v5.2 不会回退它。

### 6. 打印预览按钮
- main.xul 主工具栏「全消」（btn_selnone）后加分隔符 + `btn_print` 按钮：label=打印预览、`oncommand="Printer.preview()"`（照财务表单 15dka 原样，平台打印对象直调，不写 JS、不动 props）。
- 模板由 Alan 在打印设计里把做好的 .rpt 替换到本表单的打印模板位置后生效；未替换前点按走平台默认行为。
