# 销项开票申请单 v2 布局修复说明（2026-10-23）

## 问题来源

Alan 导入 v1 后反馈页面样式有问题，并补了现场截图。本版针对四件事逐项处理：
①查询头第一行与工具栏重叠；②网格表头折行叠字；③网格未撑满、横向滚动条游离；④运行时页签标题显示「未命名表单」。
v2 的改动全部落在 `content/main.xul` 一个文件内（坐标数值 + ds_apply 列宽），功能代码（JS/宏/props）零改动。

## 一、查询头压工具栏（坐标审计）

坐标系：本平台 stack 内控件坐标以窗口左上为原点，工具栏渲染在窗口顶部约 0..27px 的带内——实证：生产表单「销项发票申请」内容面板 `top:27px`、「客户资料维护」查询面板 `top:27px`，内容一律从 27px 起排。

全量解析 v1 成品包 main.xul 的 12 个可视控件矩形逐对求交：**重叠 6 对，全部是查询头第一行压工具栏带**（交叠总面积 14,680 px²）：

| 被压控件 | 交叠 | 面积 |
|---|---|---|
| tb_client（客户名称输入框） | 230×19 | 4,370 px²（20px 高里 19px 在带内） |
| tb_billcode（出库单号输入框） | 170×19 | 3,230 px² |
| tb_saleman（业务员输入框） | 140×19 | 2,660 px² |
| label1 / label3 / label2（三个标签） | 整高 17px 在带内 | 1,870 / 1,360 / 1,190 px² |

根因：v1 的 xul（移植自服务器直建版）查询头从 top:8 起排，未给工具栏带留 27px。
修复（13 个坐标数值）：行 1 六控件 `top:8→35`（带下留 8px）；行 2 五控件 `top:36→63`（行距 pitch 28 不变，行内标签→输入的 6px 间隙原本统一未动）；网格 `top:64→91`。

## 二、网格表头折行叠字（列宽）

**先定标题来源**：截图里的表头是「单据序号 / 登记发票数量 / 登记发票金额 / 是否开具发票」——与 ds_apply format 里自带的短标题（行号/已登记量/已登记额/自动开票）不一致，与 **SaleOutDt/SaleOutMt 数据字典注释逐字一致**（harvest 字典实证：BillSn=单据序号、K_RegInvoiceNum=登记发票数量、K_RegInvoiceAmt=登记发票金额、KF_IsInvoice=是否开具发票）。即运行时网格按字段 id 取列宽（format 的 w）、按字典注释显示标题；原 w 是照短标题定的，对 6~8 字的字典标题必然折行，「是否开具发票」列（w=62）在截图里窄到汉字逐字竖排。

修复：ds_apply format 内 8 个字段的 w 按「显示标题字数×13+余量」加宽（仅改 w，字段 id/顺序/类型/标题/其余属性逐一不变，脚本断言）：

| 字段 | 显示标题 | w |
|---|---|---|
| BillSn | 单据序号 | 45 → 70 |
| InvoiceType | 发票类型 | 60 → 76 |
| KF_IsInvoice | 是否开具发票（截图作是否自动开具发票，按 8 字留量） | 62 → 124 |
| Unit | 单位 | 50 → 70 |
| K_RegInvoiceNum | 登记发票数量 | 90 → 104 |
| K_RegInvoiceAmt | 登记发票金额 | 100 → 104 |
| BalNum | 可申请余额量 | 100 → 110 |
| KF_KFPSQ | 是否发票申请 | 62 → 100 |

复验：全部 26 个可见列按「显示标题（字典注释与 format 标题取更长者）字数×13+14」逐列审计，**均可单行显示**；可见列宽总和 2,468px > 网格宽 1,184，超出由横向滚动承担，属正常。注：format 内 KF_IsInvoice 的标题本就是短名「自动开票」，但运行时显示的是字典注释，字典是全系统共享的、不在本包修改范围，故靠加宽解决，未改任何标题文字。

## 三、网格未撑满 / 横向滚动条游离

v1 网格 1184×640、top:64，底边 704，距窗口高 760 留 56。本版网格 `top:91、height:653`，底边 744，**下边距 16 与右边距 16 一致**，在表单设计尺寸（1200×760）内已填满查询头以下的全部可视区；autoheight 本就是 N（网格不会按行数收缩）。横向滚动条是网格自身的（列宽总和 2,468 必然有），位置在网格底边——网格撑满后它落在窗口底部，不再游离在页面中部。说明一句边界：本平台表单是定尺寸布局（参照表单皆然），若门户页签实际高度大于 760，表单本体仍按 760 渲染、下方留白是平台行为，不在表单包可调范围。

## 四、标题显示「未命名表单」核查（包内无此问题，不改包）

全包 6 个成员 grep「未命名表单」= **0 命中**。包内全部标题来源逐一核对均为「销项开票申请单」：props 的 `caption` 与 `cl={'default':'销项开票申请单'}`、xul window 的 `label`、desc.html、locale 的 form.properties `title=`、加密 label 解开后亦无旧名。
结论：运行时页签标题不取以上任一包内字段，而是**取菜单节点名**——该 formid 是 Alan 在自己 Studio 里以「未命名表单」新建的空白表单，他环境里对它的既存登记名就是未命名表单，导入实例包不会改这个名字。处理：**挂菜单时把节点命名为「销项开票申请单」**（或在 Studio 表单管理里把该表单显示名改过来）即可，包无需修改。
