## 功能一句话

三页签查询/处理型表单：
- **蓝字发票申请**：按客户/业务员/出库单号/日期提取可申请的出库行 → 填本次申请量/额 → 保存写回出库单（累加已申请额/量、置申请标记、单头记申请人/时间）；支持撤销申请释放额度。余额口径：**可申请余额 = 含税额 − greatest(已登记额, 已申请额)**（数量同理），与设计文档 §3.2 定案一致。
- **红字发票申请**：同上，但对象是退货类单据行；界面按「大小」填正数，落库自动为负数（与已登记额同符号空间）；余额口径为绝对值空间的同构式：|含税额| − max(|已登记额|, |已申请额|)。列表带原出库单号、原发票号、对应蓝字发票行三列，方便对着原蓝字发票核对。
- **已申请数据的查询**：只读台账，蓝字/红字已申请行同页（申请类型列区分），展示已申请量/额、已登记量/额、申请人/申请时间与推导状态（待开票/部分开票/已开完）。

## 导入步骤

1. **先执行前置 DDL**（见下节）——顺序不能反。
2. 打开 FormStudio（开发工具），用「导入表单」选本 zip 导入。
3. 导入后在**实例组织**的表单清单里按 formid `1te8rhm10anw30hi` 或名称「销项开票申请单」确认在位。
4. 在系统里把该表单**挂菜单并给开票相关角色授权**（菜单/授权在系统内操作，导入包不含）。
5. 按文末实测清单逐项验一遍再投入使用。

## 前置 DDL（必须先于导入/使用执行，与 v1-v3 相同，红字无新增）

脚本：随包附 `新增列DDL.sql`（v4 版，与归档同份）。内容：

- `SaleOutDt` 加 `K_ApplyInvoiceAmt DECIMAL(14,2) DEFAULT 0 NOT NULL`、`K_ApplyInvoiceNum DECIMAL(14,4) DEFAULT 0 NOT NULL`
- `SaleOutMt` 加 `K_ApplyUser CHAR(11)`、`K_ApplyTime DATE`

执行要点：挑低峰窗口执行；**执行后在平台数据字典里登记这 4 列**（注释建议见脚本头）。未执行 DDL 时打开表单提取/保存会因列不存在报错（ORA-00904），属预期，不是表单坏了。申请标记复用既有闲置列 `SaleOutDt.KF_KFPSQ`（已验出库单代码零引用），无需加列；**红字经取证共用同一套申请列，亦无需加列**（取证结论见《v4三页签重建说明.md》第二节）。

## 与服务器直建版的关系（防混淆）

服务器上已有一张同功能的直建表单 `1qnyaq9q8shnwbas`（v1.1.82.2），目前仍是**单页蓝字版，未同步三页签**。本包是同一业务的另一载体（挂在 Alan 自建空白表单的身份之下）。若把本包导入同一台服务器，两张表单会并存、写同一批出库单字段——**正式使用请二选一，菜单只挂实际使用的那张**，避免两处入口混用造成理解混乱。

## 导入后实测清单

1. 提取（蓝字页）：列表只出现可申请余额 > 0 的出库行；已申请满/已登记满的行不出现。
2. 填超额（本次 > 余额）：保存被拦且回执点名单号行号与原因。
3. 正常保存后回查库：`SaleOutDt` 对应行 `K_ApplyInvoiceAmt/K_ApplyInvoiceNum` 已累加、`KF_KFPSQ='Y'`；`SaleOutMt` 单头 `K_ApplyUser/K_ApplyTime` 已留痕。
4. 撤销申请：申请额/量降至已登记额/量，未开部分额度释放；双零时 `KF_KFPSQ` 回 `'N'`；释放后可再次申请。
5. 一批提取含多客户/多业务员时保存被拦并点名（同批须同客户+同业务员）。
6. 两人同时对同一行保存：后者被旧值守卫拦截、回执点名，不出现超额累加。
7. （版面）三页签标题为「蓝字发票申请 / 红字发票申请 / 已申请数据的查询」；蓝字页列序与 v3 一致（单据序号、是否自动开具发票两列隐藏，申请标记为勾选框，本次申请两列在最右端）。
8. 红字提取：只出现退货类单据行；已登记过蓝字发票的退货行带原发票号/对应蓝字发票行。
9. 红字保存：填正数保存后回查库，申请额/量落为负数累加、`KF_KFPSQ='Y'`；超大小余额被拦并点名。
10. 红字撤销：申请额降至已登记额（负值）；已登记为 0 时撤销到 0、标记回 `'N'`。
11. 查询页：蓝字与红字已申请行同页、申请类型正确；状态与登记进度一致；单元格不可编辑，主工具栏写按钮在本页不可见。
12. （闸口第二包上线后）本表单保存过的行应出现在财务表单 15dka 的蓝字/红字页列表中；闸口未上线前 15dka 列表口径未变，属预期。
